DESIGN:
  - A - per-actor store instead of discarding on an actor switch: one tenant's operation is never shown as another tenant, and switching back shows it again, so the lock and key also survive an Alice -> Bob -> Alice round trip. The store is created per mounted App (useState), not as a module singleton, so tests are isolated and nothing global lingers.
  - A - the lock is the store state itself (status 'submitting' is checked and set synchronously), so there is no gap between a guard ref and React state.
  - A - re-selecting the already selected course is ignored. A browser sends no change event for that, but Playwright's selectOption does, and the auditors' own reproduction steps would otherwise dismiss the result they had just waited for.
  - B/E - one helper, writeOutcome(error), decides for both writes what may be claimed: 'not_run' (503 database_busy), 'rejected' (4xx), 'unknown' (everything else, including non-ApiErrors).
  - D - a parseable but malformed 2xx is ApiError status 0 (code 'invalid_response') rather than its real status, so that for the two writes it counts as an unknown outcome instead of 'rejected'. Validation is structural (what the components dereference), not a full schema; the error boundary is the net for the rest.
  - D - the error boundary lives in the default App export rather than main.jsx, so every test that mounts <App /> exercises the real wiring. Recovery is a full page reload.
  - E - the dialog stays open after an unknown outcome and keeps 'Try again'; a server-confirmed revocation adds a status line instead of closing or replacing the message.
  - G - the export is tied to the page: aborted on actor switch and on tab navigation alike. The simpler rule was preferred over an App-level abort that would let a same-actor export finish invisibly in the background.
  - H - happy-dom over jsdom (see devDependencies); the Vitest config sits in the existing vite.config.js `test` key so the build config is not coupled to a second file; fake timers are limited to setTimeout/clearTimeout and only in the debounce tests.
  - H - fixtures are recorded, not hand-written, and the recorder is committed so they can be regenerated when the API changes; tests take run-dependent values (timestamps) from the recording instead of hard-coding them.
